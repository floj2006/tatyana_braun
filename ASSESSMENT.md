# Оценка проекта: сайт Татьяны Браун, ведущей праздников

Состояние на момент сборки: React 19 + Vite, серебристая тема, без бэкенда.
Что проверено автоматически: `npm test` (5 тестов), `npm run build`, `npm audit` (0 уязвимостей),
прогон собранной версии в Chromium с включённой CSP (нарушений нет), форма и буфер обмена, 1280px и 390px без горизонтальной прокрутки.

**Ограничения оценки.** Страница VK закрыта без входа, реальных данных о трафике, ценах и клиентах Татьяны у меня нет.
Конкурентов я изучала по поисковой выдаче и описаниям (сайты не открывала), поэтому выводы по нише — это ориентиры, а не замеры.

---

## 1. Бизнес-аналитика

### Модель сайта
Сайт — «визитка-конвертер»: человек пришёл из VK или поиска, оценил стиль, написал Татьяне. Продажа происходит в переписке, а не на сайте. Поэтому единственная конверсионная цель — **начатый диалог** (клик по VK/Telegram или собранное сообщение).

### Воронка и что на каждом шаге делает сайт
| Шаг | Что должно произойти | Элемент сайта |
|---|---|---|
| 1. Первый экран | «Это мой формат, мне нравится стиль» | Оффер, портрет, кнопка «Проверить свою дату» |
| 2. Доверие | «Она реально проводит такое» | Видео-визитка, фото, отзывы |
| 3. Ясность | «Понятно, что и как, и это не безумно дорого» | Форматы, шаги, FAQ |
| 4. Действие | «Напишу» | Форма-сборщик, кнопки VK/Telegram, плавающая кнопка |

### Что заложено для измерения
Подключена лёгкая обёртка над Яндекс.Метрикой (`src/lib/analytics.js`), по умолчанию **выключена** (`SITE.metrikaId` пуст). Цели:
`cta_click` (place: header/hero/about/package/fab), `click_vk`, `click_telegram`, `click_showreel`, `event_select`, `form_submit`, `faq_open`.

**Главная метрика:** `(click_vk + click_telegram + form_submit) / визиты`. Дополнительно: доля визитов с `click_showreel`, глубина скролла до блока «Форматы», какие `event_select` встречаются чаще (подскажет, на каких праздниках делать акцент).

### Сильные стороны
- Один понятный призыв на каждом экране, мобильная версия с плавающей кнопкой (мобильный трафик из VK будет основным).
- Форма снижает барьер: готовый текст сообщения вместо пустого поля «напишите ведущей».
- Прозрачность: нет выдуманных цифр и отзывов, то, чего нет, скрывается.

### Риски и слабые места (по убыванию влияния)
1. **Нет видео-визитки и реальных фото.** Для ведущего это главный фактор доверия. Сейчас стоят серебристые заглушки; пока они не заменены, сайт слабее VK-страницы Татьяны. *Действие:* добавить 1 короткое видео (30–60 с) и 6 фото с праздников.
2. **Нет отзывов.** Блок показывает приглашение читать их во VK. *Действие:* вынести 3–6 реальных отзывов (с разрешения авторов) в `REVIEWS` в `src/config/site.js`.
3. **Нет цен.** Все форматы — «по запросу». Часть посетителей уйдёт, не спросив. *Гипотеза для теста:* показать «от N ₽» хотя бы по одному формату (`price` в `PACKAGES`) и сравнить конверсию.
4. **Состав форматов («Ведение», «Сценарий и ведение», «Под ключ») — моя гипотеза**, а не реальные услуги Татьяны. Согласовать с ней до публикации.
5. **Зависимость от VK как единственного канала.** Telegram не указан; кнопки скрыты. Если трафик идёт с VK — это нормально, но стоит добавить второй канал и телефон/WhatsApp, если они есть.
6. **Нет аналитики до включения Метрики.** Без неё оценить сайт невозможно. Включить в первый же день публикации (см. раздел «Безопасность» про CSP и 152-ФЗ).
7. **SEO ограничено.** Одностраничник на React без пререндера: для запросов вроде «ведущая свадьбы [город]» нужен город в тексте и, возможно, отдельные страницы услуг. Для трафика из VK это не критично.

### План проверки гипотез (первые 4–6 недель)
1. Включить Метрику, зафиксировать базовую конверсию.
2. Добавить видео и отзывы → смотреть `click_showreel` и конверсию.
3. A/B: показать цену «от N ₽» против «по запросу».
4. A/B: текст главной кнопки («Проверить свою дату» против «Написать Татьяне»).
Объём трафика у персонального сайта небольшой, поэтому A/B-тесты проводить последовательно, а не параллельно, и ждать не менее 2–3 недель на вариант.

## 2. Дизайн

### Референсы (из поиска)
- Кейсы свадебных агентств и ведущих: тёмная база с нежными акцентами, крупное эмоциональное фото на первом экране, видео-визитка, отзывы, цены по видам мероприятий ([workspace.ru](https://workspace.ru/cases/lending-dlya-svadebnogo-agentstva/), [гайд Tilda по сайту ведущего](https://tilda.cc/ru/tpls/sozdanie-saita-vedushego/)).
- Люкс-стилистика свадебной тематики: нейтральные тона, изящные антиквы, много воздуха, закруглённые рамки фото ([Wix Royal Ribbon](https://www.wix.com/marketplace/template/7b9df449-bd9b-4f1d-b0b2-055f8fcdb3bc), [DesignCrowd](https://www.designcrowd.com.au/jobs/job/1549646)).
- Готовых макетов именно с серебряной палитрой для ведущих я не нашла, поэтому серебро собрано самостоятельно из этих принципов.

### Решения
- **Палитра.** Серебряная шкала `#f8f9fb → #1a1d23` (холодные серо-голубые оттенки) плюс «хромовый» градиент для кнопок, рамки портрета и акцентных деталей. Один цветовой акцент вместо многоцветия: серебро выглядит дорого, если не разбавлять его.
- **Типографика.** Cormorant Garamond (антиква с кириллицей) для заголовков, Manrope для текста. Контраст тонкой антиквы и чистого гротеска создаёт «журнальный» вид.
- **Ритм.** Чередование светлых и тёмных секций (светлая → тёмный «Обо мне» → светлые → серебристые → тёмная контактная) удерживает внимание на длинной странице.
- **Форма портрета.** Арка с серебряной рамкой — узнаваемый приём свадебной тематики.
- **Выделение формата.** Средний пакет тёмный и приподнят, это направляет выбор.

### Проверено
- Контраст (WCAG): основной текст 16:1, приглушённый 7,3:1, малый серый заголовок 4,65:1, светлые тексты на тёмном 10,5:1, подвал 8,2:1. Ниже 4,5:1 только два декоративных крупных элемента (светлый край градиентного слова в H1 — 3,0:1; номера карточек — 3,2:1), для крупного текста порог 3:1 выполнен.
- Адаптив: 1280 и 390 пикселей, без горизонтальной прокрутки. На телефоне первый экран начинается с заголовка и кнопки (в первой версии портрет вытеснял кнопку за экран; исправлено).
- Доступность: ссылка «К содержимому», видимый фокус, aria-метки, нативный `<details>` для FAQ, учёт `prefers-reduced-motion`.

### Что ещё слабо
- **Заглушки вместо фото** — главный недостаток визуально. Серебристая пластина смотрится стильно, но живых людей не заменит. Серебряная палитра хорошо работает с чёрно-белыми или холодными по тону фото; цветные тёплые снимки лучше слегка согласовать по тону.
- **Видео** пока кнопка-ссылка на VK, а не встроенный плеер (из-за строгой CSP). Если захотите встроенное видео, придётся расширить CSP на домен плеера VK.
- Нет страниц отдельных услуг и портфолио с историями — при росте сайта стоит добавить.
- Тёмный режим системы не поддерживается намеренно: серебристая тема сама по себе завершённая; переключение не добавляла.

## 3. Безопасность

### Модель угроз
Статический сайт без бэкенда, без аккаунтов, без хранения данных и без секретов. Основные риски: подмена контента или ссылок, XSS, утечка данных посетителей на сторонние сервисы, захват хостинга/домена.

### Что реализовано
| Мера | Где |
|---|---|
| Строгая CSP: `default-src 'self'`, `script-src 'self'`, `style-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'none'` | meta в сборке (`vite.config.js`) и `public/_headers` |
| Заголовки: `X-Content-Type-Options`, `X-Frame-Options: DENY` и `frame-ancestors 'none'`, `Referrer-Policy`, `Permissions-Policy`, HSTS, COOP | `public/_headers` |
| Нет inline-скриптов и inline-стилей (поэтому CSP без `unsafe-inline`); фото сделаны как `<img>`, а не `style` | компоненты |
| Нет `dangerouslySetInnerHTML`, `eval`, динамических HTML-вставок; React экранирует весь вывод | весь `src/` |
| Внешние ссылки только через `safeUrl`: https и белый список хостов (`vk.ru`, `vk.com`, `t.me`), иначе ссылка скрывается | `src/config/site.js`, тесты |
| `target="_blank"` всегда с `rel="noopener noreferrer"` | все внешние ссылки |
| Форма ничего не отправляет: текст собирается и копируется в браузере; поля чистятся от управляющих символов и ограничены по длине, от «подделки» строк сообщения есть тест | `src/lib/message.js` |
| Шрифты хостятся локально (`@fontsource`), не с Google: нет передачи IP посетителей стороннему CDN, строгая CSP не нужна для шрифтов | `src/main.jsx` |
| Зависимости: 4 прямых (`react`, `react-dom`, 2 шрифта), `npm audit` — 0 уязвимостей, версии зафиксированы в `package-lock.json` | `package.json` |
| Аналитика выключена по умолчанию; при включении грузится только после явной настройки | `src/lib/analytics.js` |

### Остаточные риски и что сделать вам
1. **Заголовки зависят от хостинга.** `public/_headers` понимают Netlify и Cloudflare Pages. На GitHub Pages заголовки задать нельзя (работает только meta-CSP, без `frame-ancestors` и HSTS). Для nginx/Apache перенесите их в конфиг. Рекомендуется Cloudflare Pages или Netlify; на Vercel заголовки переносятся в `vercel.json`.
2. **Включение Яндекс.Метрики ослабляет CSP.** Нужно добавить `https://mc.yandex.ru` в `script-src`, `connect-src`, `img-src` (точная строка в комментарии `analytics.js`). Метрика собирает данные посетителей, поэтому нужна **политика обработки персональных данных и уведомление о cookie** (152-ФЗ). Сейчас без Метрики сайт данных не собирает, и политика не требуется.
3. **Домен и аккаунт хостинга — главная точка захвата.** Включите двухфакторную защиту на регистраторе, хостинге и GitHub, подключите автопродление домена. Подмена `SITE.vk` в репозитории или на хостинге — самый вероятный сценарий атаки (мошенническая ссылка вместо VK Татьяны).
4. **Защита репозитория.** Включите защиту ветки `master`, обязательные ревью и 2FA; Dependabot для обновлений.
5. **Нет CI.** Рекомендуется GitHub Actions: `npm ci && npm test && npm run build && npm audit --omit=dev`.
6. **Данные в сообщениях.** Посетитель сам вставляет сообщение в VK; сайт этого не видит. Но VK и Telegram — сторонние сервисы со своими политиками; сайт честно пишет, что сам ничего не хранит.
7. **Фишинг через имя.** Если Татьяна использует собственный домен, зарегистрируйте и похожие варианты (например, `.ru`/`.com`), чтобы их не заняли мошенники.

### Итог по безопасности
Для статического сайта без сбора данных это сильная база: нет бэкенда и данных — нет и большинства классов уязвимостей. Основные риски организационные (домен, хостинг, учётные записи), а не кодовые.

## Приоритеты перед запуском
1. Фото и видео-визитка → `public/img/`, `SITE.showreelUrl`.
2. Реальные отзывы → `REVIEWS`.
3. Подтвердить форматы и цены с Татьяной → `PACKAGES`.
4. Указать Telegram (если есть) → `SITE.telegram`.
5. Выбрать хостинг с поддержкой заголовков, включить 2FA и автопродление домена.
6. Включить Метрику вместе с политикой конфиденциальности.
