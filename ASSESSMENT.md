# Оценка проекта

React 19 + Vite, без сервера. Проверено: `npm test` (5 тестов), `npm run build`, `npm audit` (0 уязвимостей), собранная версия в Chromium с включённой CSP (нарушений нет), форма и копирование в буфер, ширины 1280 и 390 без горизонтальной прокрутки.

Что я не знаю. Страница VK закрыта без входа, поэтому о Татьяне, трафике и ценах у меня нет данных. Конкурентов я смотрела по описаниям в поиске, сами сайты не открывала. Все выводы про нишу ориентировочные.

## Главный вывод

Первая версия выглядела как нейросетевой шаблон: шесть карточек в сетке, «четыре простых шага», три тарифа, общие фразы про «индивидуальный подход». Тексты были моими, а не её. Теперь на сайте только то, что известно точно: имя, что она ведёт праздники, ссылка на VK. Блоки без материалов (о себе, отзывы, фото, видео) не показываются, пока в `src/config/site.js` и `public/img/` ничего нет. Пустых заглушек на сайте нет.

Из этого следует главное ограничение: **сайт станет сильным только с её материалами**. Они перечислены в `QUESTIONS.md`.

## Бизнес

Цель одна: чтобы человек написал Татьяне. Продажа происходит в переписке, поэтому сайт должен убедить, что с ней стоит говорить.

Что мешает конверсии сейчас, по важности:
1. Нет видео. Для ведущего это основной довод.
2. Нет отзывов и фото с праздников.
3. Нет её голоса: ни одной фразы и истории от неё самой.
4. Нет цен. Часть людей уходит, не спросив. Стоит проверить показ «от N ₽».
5. Один канал связи (VK). Если есть Telegram, телефон или WhatsApp, их надо добавить.

Аналитика подготовлена и выключена (`SITE.metrikaId`). Цели: `click_vk`, `click_telegram`, `click_showreel`, `cta_click`, `event_select`, `form_submit`. Главный показатель: `(click_vk + click_telegram + form_submit) / визиты`. Включать вместе с политикой обработки персональных данных (152-ФЗ) и расширением CSP, строка есть в `src/lib/analytics.js`.

Для поиска по запросу вроде «ведущая свадьбы + город» одностраничник на React слабоват: нужны страницы под каждый повод с городом в тексте и пререндер. Если трафик идёт из VK, это не срочно.

## Дизайн

Референсы из поиска: кейсы свадебных агентств и сайты ведущих строятся вокруг видео и реальных отзывов ([Workspace](https://workspace.ru/cases/lending-dlya-svadebnogo-agentstva/), [гайд Tilda](https://tilda.cc/ru/tpls/sozdanie-saita-vedushego/)). Серебряной палитры именно для ведущих я не нашла и собрала сама.

Решения:
- Серебряная шкала от `#f8f9fb` до `#1a1d23`, металлический градиент только на кнопке в тёмном блоке и на кнопке воспроизведения.
- Шрифты Cormorant Garamond и Manrope, лежат в проекте.
- Первый экран держится на крупном имени. Праздники в виде списка с тонкими линиями, фото кладкой колонками. Карточек, иконок и декоративных значков нет.
- Контраст: основной текст 16:1, приглушённый 7,3:1, светлый на тёмном 10,5:1, подвал 8,2:1.
- Доступность: ссылка «К содержимому», видимый фокус, `prefers-reduced-motion`.

Слабое место: без фото и видео первый экран только шрифтовой. Это честно, но выглядит скромно. Серебро лучше сочетается с холодными или чёрно-белыми фото.

## Безопасность

Статический сайт: нет сервера, аккаунтов, хранения данных и секретов.

Сделано:
- Строгая CSP (`script-src 'self'`, `style-src 'self'`, `form-action 'none'`, без inline-кода), в сборке и в `public/_headers`. Там же `frame-ancestors`, HSTS, `nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- Внешние ссылки проходят через `safeUrl`: только https и белый список хостов (`vk.ru`, `vk.com`, `t.me`, `vkvideo.ru`). Всегда `rel="noopener noreferrer"`.
- Форма ничего не отправляет. Сообщение собирается в браузере, поля очищаются от управляющих символов и ограничены по длине, есть тест на подмену строк.
- Нет `dangerouslySetInnerHTML` и `eval`.
- Шрифты свои, без запросов к Google.
- 4 прямые зависимости, версии зафиксированы, `npm audit` чист.

Что сделать вам:
1. Заголовки из `_headers` работают на Cloudflare Pages и Netlify. На GitHub Pages их нет, остаётся только meta-CSP. На Vercel и nginx их надо перенести в конфиг.
2. Самый вероятный сценарий атаки: подмена ссылки на VK через учётную запись хостинга или репозитория. Нужна двухфакторная защита на регистраторе домена, хостинге и GitHub, автопродление домена, защита ветки `master`.
3. Метрика собирает данные посетителей: нужна политика и уведомление о cookie.
4. Нет CI. Минимум: `npm ci && npm test && npm run build && npm audit --omit=dev`.

## Что делать дальше

1. Получить от Татьяны ответы на `QUESTIONS.md`, видео и фото.
2. Написать блок «О себе» и отзывы её словами.
3. Решить с ценами и каналами связи.
4. Выбрать хостинг, включить 2FA и автопродление домена.
5. После запуска включить Метрику и смотреть, где отваливаются посетители.
